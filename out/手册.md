## 0. 先读这一段

**这个方案能做什么**：一台 ARM64、8/12/16GB 内存、256GB~1TB UFS 3.1 存储、自带电池（天然 UPS）、待机功耗约 0.5W 的 Linux 服务器。跑 nginx、PostgreSQL、Docker/Podman、编译、下载机、内网穿透都没问题。

**这个方案不能做什么 / 要接受的现实**：

| 限制 | 说明 |
|---|---|
| 快充不可用 | mainline 缺小米私有充电认证协议，只能慢充（约 5V/1A~2A）。对服务器反而好，但充满很慢 |
| 指纹 / NFC / 红外 | 无驱动，永久不可用 |
| 摄像头 | 只有主摄和超广角能出图，前摄/微距/自动对焦/闪光灯不行 |
| 电池寿命 | 长期插电满电会鼓包，**必须**做电源管理，见第 7 节 |
| 散热 | 无风扇。持续满载会降频，建议加铜片+小风扇 |
| 系统成熟度 | 社区移植（testing 分类），不是官方主线设备。出问题要自己查 |

**如果你只是想"随便跑点东西"**：先用 Termux + proot-distro 在现有 Android 上跑，确认需求真实存在再刷。刷机不可逆的部分只有分区表，但恢复很麻烦。

## 1. 物料与前置条件

### 硬件

- 红米 Note 12 Turbo（**已解锁 bootloader**，未解锁先去小米社区申请，有 7~30 天等待期）
- 一台 Linux PC（本手册用 WSL2 Ubuntu 24.04 完成构建，见附录 B）
- USB 数据线（能传数据的，不是纯充电线）
- 建议：USB-C hub + 千兆网卡（服务器要稳定有线网络）、小风扇、散热铜片

### 软件

| 工具 | 用途 | 安装 |
|---|---|---|
| `fastboot` | 刷 U-Boot | `apt install android-tools-fastboot`（Linux）；Windows 用官方 platform-tools |
| `python3` | 跑 marble-install | 系统自带 |
| `e2fsprogs` `util-linux` | 检查/扩展文件系统 | `apt install e2fsprogs util-linux` |
| `cryptsetup` | 如果用 LUKS 加密 | `apt install cryptsetup-bin` |

> ⚠️ **fastboot 版本要求**：必须支持 `set_active`。实测很老的 fastboot（2010 年代那种，帮助列表里没有 `set_active`）会直接报 `usage:` 然后什么也不做。Windows 上建议直接下载官方最新 platform-tools：
>
> ```
> https://dl.google.com/android/repository/platform-tools-latest-windows.zip
> ```
>
> 本次实测用的是 `fastboot version 37.0.1`。

### 确认 bootloader 已解锁

手机**关机**，按住 **音量下 + 电源** 进入 fastboot，然后：

```bash
fastboot devices          # 应该能看到设备序列号
fastboot getvar unlocked  # 输出 unlocked: yes 才行
```

如果输出 `no` 或报错，说明没解锁，**停止**，先去解锁。

## 2. 必须备份的分区（最关键一步）

> ⚠️ **这一步不能跳过。** `persist`、`modemst1`、`modemst2`、`fsg` 存着 IMEI 和射频校准数据。刷坏后手机会变成"能开机、能连 Wi-Fi、但没有蜂窝信号"的半砖，**无法通过任何公开手段恢复**（小米 EDL 需要授权账号）。

### 为什么必须在手机上备份

小米的 fastboot **不允许**读取这几个分区（`fastboot getvar` 能查，`fastboot flash` 能写，但不能 `fastboot dump`）。所以备份只能在手机上以 root 身份做。

### 方法 A：刷机前用现有 Android 的 root 备份（推荐）

你的手机已经 root，直接：

```bash
adb push backup-marble.sh /data/local/tmp/
adb shell su -c "sh /data/local/tmp/backup-marble.sh"
# 想换输出位置就带上参数，例如 /sdcard/marble-backup
```

脚本默认写到 `/data/local/tmp/marble-backup/<时间戳>/`，dd 出 4 个分区镜像 + `SHA256SUMS.txt` + `device-info.txt`。然后拉到电脑：

```bash
adb pull /data/local/tmp/marble-backup ./marble-backup
```

> **脚本兼容性**：这一版是纯 POSIX sh，兼容 Android 的 mksh / toybox（不用 `declare -A` 关联数组、不用 GNU 专有选项、不用 `dd status=progress`）。实测在 Android 上能正常跑。
>
> 如果 dd 提示 `Permission denied`，说明 `su` 没真正拿到 root，先用 `adb shell su -c id` 确认输出 `uid=0`。
>
> 如果 `adb pull` 报 `0 files pulled`，是权限问题：脚本以 root 建目录（`700`），而 `adb pull` 以 `shell` 用户运行读不到。脚本结尾已经 `chmod 755/644` 处理过；若手动跑请自己补：
>
> ```bash
> adb shell su -c "chmod -R a+rX /data/local/tmp/marble-backup"
> ```

### 方法 B：刷完 pmOS 后再备份（不推荐）

如果你已经刷了 pmOS，分区还在（我们不动 sdf 上的分区），可以在 pmOS 里跑同一个脚本：

```bash
sudo ./backup-marble.sh /home/marble/marble-backup
scp -r marble@<手机IP>:/home/marble/marble-backup ./
```

### 验证备份完整性

```bash
cd marble-backup/<时间戳>
sha256sum -c SHA256SUMS.txt
```

期望大小（参考）：
- `persist.img` ≈ 32MB
- `modemst1.img` ≈ 8MB
- `modemst2.img` ≈ 8MB
- `fsg.img` ≈ 8MB

**把这四个文件在三个地方各存一份**（电脑、网盘、U 盘）。它们只有 56MB。

## 3. 刷 U-Boot 到 slot B

### 原理

```
原厂 ABL (Android bootloader, slot A)
   └─> boot_b 里的 U-Boot          ← 我们刷这里
          └─> esp 分区 /extlinux/extlinux.conf
                 └─> Linux 内核 + initramfs + DTB
```

Android 在 slot A 完全不动，所以刷坏了还能切回 Android。

### 操作

手机进入 fastboot（关机 → 音量下 + 电源），然后：

```bash
cd out

# 1) 确认设备
fastboot devices

# 2) 查当前 slot —— 必须查两次，刚重启后第一次的答案可能是错的
fastboot getvar current-slot
fastboot getvar current-slot

# 3) 刷 U-Boot 到 boot_b
fastboot flash boot_b boot-uboot.img

# 4) 切到 slot B
fastboot set_active b

# 5) 重启
fastboot reboot
```

### 验证 U-Boot 镜像

`boot-uboot.img` 的 SHA256 必须等于：

```
81d9e7bce88b43f39262198590ce686a0c6544585ab4dbe668a8c2b3deaadb00
```

本手册附带的 `out/boot-uboot.img` 已校验通过（来自 [u-boot-marble v20261008](https://github.com/iLtanaka/u-boot-marble/releases/tag/v20261008)）。

### 进入 U-Boot 菜单

重启时**按住音量下**，或在 5 秒倒计时内按任意键。菜单项：

```
Boot Nura                    ← 默认，5 秒后自动启动
Other systems...             ← 需要 esp 上有 others.env
Serial console shell         ← USB ttyACM0，调试用
Enable USB mass storage      ← 把内部存储导出成 U 盘，下一步要用
Enable fastboot mode
Drop to shell / reset / poweroff
```

按键：**音量加/减**移动光标，**电源键**确认（⚠️ 注意不要停在 `8. Power off` 上按电源，详见 4.1）。

## 4. 写入 pmOS 镜像

### 4.1 让手机导出内部存储

**U-Boot 菜单的按键操作**（这台机器只有三个物理键，没有触摸）：

| 操作 | 按键 |
|---|---|
| 上下移动光标 | **音量加 / 音量减** |
| 确认选中（ENTER） | **电源键** |
| 退出大容量存储模式 | 任意按键 |

> ⚠️ 这里有个致命混淆：菜单里 `8. Power off` 就在列表靠后。**高亮停在那一行时按电源键 = 关机**，表现很像"电源键就是关机键"，容易误判。按之前务必看清白色高亮条在哪一行。

> 🔴 **实测警告：本机的 UMS 不可用。**
> 在真机上选中 `4. Enable USB mass storage` 后，屏幕变黑、**整个 USB 设备从总线消失**，电脑端完全看不到磁盘（换直插主板后置 USB 口也一样）。
> 所以下面这条路径在 u-boot-marble v20261008 + 本机上是走不通的，**请直接看 4.0 的替代方案**。

### 4.0 替代方案：GPT 手术 + fastboot 按分区名烧写（**实测可用**）

完整步骤见仓库根目录 **`DEPLOY.md`** 第 4 节。要点：

1. 在 Android 里 dump 原始 GPT，PC 上用 `scripts/D0-make-gpt.py` 把 `userdata` 表项换成 `esp`(1G) + `pmos`(剩余)，校验 CRC 后 dd 写回（只碰 LBA0..33 和磁盘末尾的备份，不破坏任何文件系统）
2. ABL 会认到新分区：`fastboot getvar partition-size:esp` → `0x40000000`
3. `fastboot flash esp xiaomi-marble-boot.img` （raw，512MB 直接烧）
4. **`root.img` 必须先转 sparse 再烧**，否则会被截断：

   ```bash
   img2simg xiaomi-marble-root.img root.simg 1048576
   fastboot flash pmos root.simg
   ```

   原因：997MB 超过 ABL 单块上限 768MB，fastboot 会按 sparse 分块发；文件不是 sparse 时只发 710MB，`Writing` 只用 0.01 秒，数据不完整。`deviceinfo_flash_sparse="true"` 就是在说这件事。
5. `fastboot set_active b` → 重启

### 4.1（原方案，本机不可用，留作参考）让手机导出内部存储

选中 `Enable USB mass storage` 后，电脑上会多出一块 **4096 字节逻辑扇区** 的磁盘（Linux 下通常是 `/dev/sdX`）。

> ⚠️ 只有 **UFS LUN 0** 会被导出。启动链（xbl/abl 所在 LUN 1/2/4/5）电脑根本看不到，所以**不可能误刷坏引导链**。这是这个方案最安全的设计。

### 4.2 检查磁盘

```bash
cd out
sudo ./marble-install list
```

应该输出类似：
```
/dev/sdb  Xiaomi  UMS
```

如果有多个候选或没有输出，先别继续，检查是不是只插了手机。

查看分区表：
```bash
sudo ./marble-install show
```

会打印 `super`、`userdata` 等分区。脚本会验证指纹分区（`super`/`metadata`/`devinfo`/`vbmeta_system_a`）和 4096 字节扇区，防止刷错盘。

### 4.3 选择布局

| 布局 | 命令 | 结果 |
|---|---|---|
| **单系统**（推荐给服务器） | `--layout single` | 删掉 `userdata`，全盘给 Linux。Android 不再启动 |
| 双系统 | `--layout dual --pmos-size 64G` | 缩小 `userdata`，Android 保留但要擦数据 |
| 重装 | `--layout reinstall` | 复用已有 `esp`/`pmos`，只重写镜像 |

**服务器场景用 single**：不需要 Android，全盘给 Linux 更省心。

### 4.4 先空跑

```bash
sudo ./marble-install install --layout single --dry-run \
    --boot-img  /path/to/xiaomi-marble-boot.img \
    --root-img  /path/to/xiaomi-marble-root.img
```

会打印分区计划（创建 esp 1G、创建 pmos 剩余全部、删除 userdata），**不写盘**。确认无误再执行。

### 4.5 正式写入

```bash
sudo ./marble-install install --layout single \
    --boot-img  /path/to/xiaomi-marble-boot.img \
    --root-img  /path/to/xiaomi-marble-root.img \
    --backup-dir ./backup-gpt
```

脚本会：
1. 把旧分区表存到 `backup-gpt/marble-lun0-gpt-<时间戳>.bak`
2. 创建 `esp`(1G, ext2, label `pmOS_boot`) 和 `pmos`(剩余, ext4, label `pmOS_root`)
3. `dd` 写入两个镜像并逐字节校验
4. 扩展文件系统填满分区

中途会要求输入 `erase userdata` 确认（防手滑）。

### 4.6 用封装好的脚本（可选）

`out/flash-marble.sh` 把第 3、4 步合在一起：

```bash
# 第 1 步：fastboot 刷 U-Boot
sudo ./flash-marble.sh --step1

# 手机进 U-Boot -> Enable USB mass storage
# 第 2 步：写镜像
sudo ./flash-marble.sh --step2
```

环境变量：`BOOT_IMG` `ROOT_IMG` `UBOOT_IMG` `LAYOUT` `PMOS_SIZE` `DRY_RUN`。

## 5. 首次启动与 SSH 接入

### 5.1 启动

手机上按任意键退出大容量存储模式，选 **Boot Nura**（或等倒计时）。

- 屏幕会黑一两秒（`marble-panel-on.service` 在切帧缓冲），正常
- 首次启动会自动扩展根文件系统、生成 SSH host key，需要 1~2 分钟
- 如果用了 LUKS 加密，会在触摸屏上要求输密码

### 5.2 联网

**方式 A：Wi-Fi**（首次启动需要先在本地配置，或插 USB 网络）

**方式 B：USB 网络（推荐首次接入）**

手机用 USB 连电脑后，会在电脑上出现一个网卡（RNDIS，`172.16.42.1` 是手机端）：

```bash
# 电脑上
ip addr                       # 找到新增的 usb0/enx... 网卡
sudo ip addr add 172.16.42.2/24 dev <网卡名>
sudo ip link set <网卡名> up
ssh marble@172.16.42.1
```

默认密码在 `pmbootstrap install` 最后会打印出来。如果忘了：

```bash
# 在构建机上重新设置
pmbootstrap config user
pmbootstrap install --split   # 重跑会重新生成
```

> ⚠️ USB 网络 gadget 会让充电器识别成"下游设备"，把充电限到 5V/1A。长期用 USB 网络时要注意电量。

**方式 C：Wi-Fi 命令行配置**

```bash
sudo nmcli device wifi list
sudo nmcli device wifi connect "<SSID>" password "<密码>"
```

### 5.3 确认系统状态

```bash
uname -a                    # 应该看到 7.2.8 内核
cat /etc/os-release         # postmarketOS / Nura
systemctl --failed          # 应该没有 failed
ip addr                     # 确认拿到 IP
```

## 6. 服务器化配置

跑 `out/setup-server.sh`（在手机上以 root 执行）：

```bash
sudo ./setup-server.sh
```

它会做：
1. `apk update && apk upgrade`
2. 装 openssh / htop / tmux / git / vim / nginx 等
3. 设时区 `Asia/Shanghai`、主机名 `marble`
4. 创建用户 `marble` 并加入 wheel 组，配置 sudo
5. SSH：禁用 root 登录、启用公钥、启动 sshd
6. 部署 `/usr/local/bin/temp-monitor.sh`（每分钟记录温度/电量）

### 手动关键配置

**SSH 加固**（`/etc/ssh/sshd_config`）：

```
PermitRootLogin no
PasswordAuthentication no          # 配好公钥后关掉密码登录
PubkeyAuthentication yes
```

**防火墙**（pmOS 用 nftables）：

```bash
apk add nftables
cat > /etc/nftables.nft <<'EOF'
table inet filter {
    chain input {
        type filter hook input priority 0; policy drop;
        ct state established,related accept
        iif lo accept
        tcp dport 22 accept
        tcp dport { 80, 443 } accept
        icmp type echo-request accept
    }
}
EOF
rc-update add nftables default 2>/dev/null || systemctl enable nftables
```

**查看温度**：

```bash
for z in /sys/class/thermal/thermal_zone*; do
    echo "$z: $(( $(cat $z/temp) / 1000 ))°C"
done
```

**查看电池**：

```bash
cat /sys/class/power_supply/battery/capacity
cat /sys/class/power_supply/battery/status
```

### 6.5 可选：屏幕上的状态面板（kiosk）

服务器不需要桌面，但让手机屏幕显示一块状态面板很实用：一眼看到温度、负载、电量、IP。

原理：**不加桌面环境**，只用 `cage`（极简 Wayland kiosk 合成器，一次只显示一个全屏客户端）+ `cog`（WPE WebKit kiosk 浏览器），加载一个本地生成的 HTML。SSH 与所有服务完全不受影响。

```bash
# 手机上（默认：空闲 120 秒熄屏，按电源键或触摸唤醒）
scp -r dashboard marble@<手机IP>:~/
ssh marble@<手机IP>
cd dashboard && sudo ./install-dashboard.sh

# 想改空闲时长
sudo IDLE_SEC=300 ./install-dashboard.sh
# 只装面板、不用熄屏
sudo ./install-dashboard.sh --no-idle

# 手动控制
marble-screen.sh off      # 立刻熄屏
marble-screen.sh on       # 立刻亮屏
marble-screen.sh status   # 看当前状态
```

要点：

| 项目 | 说明 |
|---|---|
| 数据来源 | 纯 busybox + sysfs（`/proc/loadavg`、`/sys/class/thermal/*`、`/sys/class/power_supply/*`），不需要 Python/Node |
| 刷新 | 生成脚本每 2 秒重写 HTML，页面每 2 秒 reload |

| **空闲熄屏** | 空闲 `IDLE_SEC` 秒（默认 120）自动熄屏 |
| **唤醒** | 按电源键、摸屏幕、按音量键——任何输入事件都立刻亮屏 |
| **电源键不关机** | 装了 `/etc/systemd/logind.conf.d/99-marble-powerkey.conf`，`HandlePowerKey=ignore`。硬件级长按仍可强制断电 |
| 熄屏方式 | `BLANK_MODE=backlight`（默认，写 brightness=0，唤醒瞬时）；可改 `kiosk`（停 cage 释放 DRM，熄得更彻底但唤醒慢 2~3 秒）或 `both` |
| 退回纯文本 | `systemctl disable --now marble-dashboard-kiosk` |
| 完全卸载 | `sudo ./install-dashboard.sh --remove` |

#### 空闲熄屏是怎么实现的（以及为什么这么做）

普通的Wayland 空闲检测要靠 compositor 暴露 `ext-idle-notify-v1` 协议，cage 是个极简合成器，不一定支持。所以这里**完全绕开 compositor**：

- `marble-screen-idle.sh` 给每个输入设备（`/dev/input/eventN`，只挑有 `EV_KEY` 或 `EV_ABS` 能力的）起一个后台循环，用 `dd bs=24 count=1` **阻塞读一个 `struct input_event`**（aarch64 上是 24 字节）。任何按键、触摸都会让它返回，于是刷新"最后活动时间"。
- 主循环每秒检查一次：空闲 ≥ `IDLE_SEC` 就 `marble-screen.sh off`；熄屏后一旦检测到输入就 `marble-screen.sh on`。
- 不依赖 `evtest`、`libinput`、Python，busybox 就够。

调参在 `/etc/systemd/system/marble-screen-idle.service.d/override.conf`：

```ini
[Service]
Environment=IDLE_SEC=120          # 空闲多少秒熄屏
Environment=BLANK_MODE=backlight  # backlight | kiosk | both
Environment=FALLBACK_BRIGHTNESS=45
```

改完 `systemctl daemon-reload && systemctl restart marble-screen-idle`。

排错：

```bash
journalctl -u marble-screen-idle -n 50 -f   # 看它监视了哪些设备、何时熄/亮
marble-screen.sh status                     # 当前状态 + 背光值
ls /sys/class/backlight/                    # 有没有背光设备
cat /proc/bus/input/devices | grep -E 'Handlers|Name'
```

> ⚠️ **如果熄屏后屏幕其实还亮着**：AMOLED 没有真正的背光，`brightness=0` 不一定能关掉面板。这时把 `BLANK_MODE` 改成 `kiosk`（停掉 cage 释放 DRM），代价是唤醒要等 2~3 秒重新拉起。
>
> ⚠️ **如果按电源键关机了**，说明 logind 的 drop-in 没生效：确认 `/etc/systemd/logind.conf.d/99-marble-powerkey.conf` 存在，并 `systemctl restart systemd-logind`（会断开当前 SSH，重连即可）。
>
> ⚠️ **AMOLED 烧屏**：屏幕是 1080×2400 AMOLED，长期显示静态高亮元素会留下永久残影。面板已用深色背景 + 低亮度 + 少量高亮元素缓解，**空闲熄屏本身是防烧屏最有效的手段**。
>
> 屏幕点亮大约多耗 0.5~1W；熄屏后基本只剩待机功耗。

> ⚠️ 如果 `apk add cage cog` 失败（某些分支没打包 `cog`），改用 `apk add cage chromium`，并把 `marble-dashboard-kiosk.service` 里的 `cog` 换成 `chromium --kiosk`。chromium 内存占用多几百 MB，优先用 cog。

## 7. 电池与散热（长期运行必读）

这是手机当服务器**最容易翻车**的地方，比软件问题重要得多。

### 问题

1. **长期满电**：锂电池在 100% SOC 且高温下循环，正极材料加速衰减，几个月就会鼓包。鼓包会顶起后盖、挤压屏幕，严重时起火。
2. **无风扇**：持续满载（编译、数据库、转码）会到 70°C+，触发降频，长期高温加速电池老化。
3. **慢充**：mainline 只能 5V/1~2A，从 0 到 100% 要 3~5 小时。

### 方案（按推荐度排序）

| 方案 | 做法 | 效果 |
|---|---|---|
| **定时插座**（最推荐） | 买个机械/智能定时插座，每天通电 8 小时、断电 16 小时 | 电量在 30~70% 区间循环，电池寿命最大化。断电期间靠电池跑，天然 UPS |
| 智能插座 + 电量联动 | 用 Home Assistant / Tasmota 监控 `/sys/class/power_supply/battery/capacity`，>80% 断电、<40% 通电 | 更精确，但要写脚本 |
| 物理断开 | 拆后盖拔电池排线，改直接供电 | 彻底解决，但失去 UPS 且需要拆机 |
| 什么都不做 | 一直插着 | **3~6 个月后大概率鼓包**，不建议 |

### 散热

- 贴一片 2mm 铜片在 SoC 位置（后盖内侧），外面加个 5V 小风扇（USB 供电）
- 或用笔记本散热底座，手机平放上去
- 监控脚本：`temp-monitor.sh` 已部署，超过 55°C 要检查
- 目标：满载 < 65°C，待机 < 40°C

### 功耗参考

| 状态 | 功耗 |
|---|---|
| 深度睡眠（无网络活动） | 约 0.3~0.6W |
| 待机（Wi-Fi 连着，SSH 可连） | 约 1~1.5W |
| 轻度负载（nginx + 数据库） | 约 2~3W |
| 满载（编译） | 约 8~12W |

按 1.5W 待机算，一年约 13 度电。

## 9. 救砖与回滚

### 情况 1：开不了机，但能进 fastboot

```bash
fastboot devices
fastboot set_active a     # 切回 Android slot
fastboot reboot
```

如果 Android 也起不来，说明 userdata 被动了（single 布局必然如此），需要重刷 Android 官方包（用小米的 MiFlash 或 fastboot 刷 `super`/`userdata`）。

### 情况 2：能进 U-Boot，但 Linux 起不来

在 U-Boot 菜单：
- **Serial console shell** → 用 USB 线连电脑，`/dev/ttyACM0` 上有串口控制台
- 检查 `/boot/extlinux/extlinux.conf` 是否正确
- 用 **Enable USB mass storage** 导出存储，在电脑上挂载 `esp` 分区检查

### 情况 3：分区表坏了

用安装时自动保存的备份：

```bash
sudo ./marble-install restore ./backup-gpt/marble-lun0-gpt-<时间戳>.bak
```

> 注意：`restore` 只恢复分区表，**不恢复分区内容**。`pmos` 里的数据会丢。

### 情况 4：IMEI 丢了 / 没信号

用第 2 节的备份恢复：

```bash
sudo dd if=persist.img  of=/dev/block/by-name/persist
sudo dd if=modemst1.img of=/dev/block/by-name/modemst1
sudo dd if=modemst2.img of=/dev/block/by-name/modemst2
sudo dd if=fsg.img     of=/dev/block/by-name/fsg
sync && reboot
```

如果没备份过 —— 只能送修或找有 EDL 授权的维修点。

## 附录 B：构建过程记录

本手册的镜像是在 **Windows 10 + WSL2 Ubuntu 24.04** 上构建的。

### 环境要点

| 项目 | 值 |
|---|---|
| 主机 | Windows 10 19045，AMD64，12 核，31GB 内存 |
| 构建环境 | WSL2 Ubuntu 24.04.4 LTS，内核 6.18.54.1-microsoft-standard-WSL2 |
| 构建目录 | `/home/<user>/marble-build`（**必须在 ext4 上**） |
| pmbootstrap | 3.12.1（git master） |
| pmaports | [iLtanaka/pmaports](https://github.com/iLtanaka/pmaports) `marble` 分支 |
| 内核 | linux-xiaomi-marble 7.2.8-r7 |
| 固件 | firmware-xiaomi-marble 20261008-r0 |
| 通道 | systemd-edge（这个移植只提供 systemd 单元） |
| UI | `console`（headless） |

### 关键坑（复现时会遇到）

1. **不能在 `/mnt/e`（9p/drvfs）上构建**。9p 文件系统不支持 `mknod`，而 pmbootstrap 的 chroot 必须创建设备节点。必须用 WSL 的 ext4 根文件系统，最后把产物拷回 Windows。

2. **`pmbootstrap init` 是纯交互向导**，无法脚本化（3.12 的 `init` 子命令只接受 `--shallow-initial-clone`）。绕过方法：手写 `~/.config/pmbootstrap_v3.cfg` + 手动创建 work 目录和 `version` 文件（内容 `8`）。

3. **pmaports 必须加 upstream remote**。设备包读 `channels.cfg` 时走 `git show <upstream>/main:channels.cfg`，没有 upstream remote 会报 `could not find remote name`。

4. **firmware 必须先单独编译**。`pmbootstrap install` 不会自动编它，直接 install 会报 `no such package firmware-xiaomi-marble-*`。

5. **github.com 直连不稳定**（TLS 中断、超时）。克隆用 `-c http.version=HTTP/1.1`，失败则退到 codeload tarball。固件 tarball 82MB 下了约 35 分钟。

6. **镜像源路径**：pmOS 实际仓库是 `mirror.nura.eco/postmarketos/main/`（不是 `edge/`），systemd 仓库是 `extra-repos/systemd/main/`。默认配置的 `mirror.postmarketos.org` 会 301 到 `mirror.nura.eco`，能正常工作。

7. **必须设置 4096 字节扇区**。手机 UFS 是 4096 字节逻辑扇区，镜像的文件系统块大小必须 ≥4096，否则挂不上。`marble-install` 会自动检查。

8. **crossdirect 在 WSL2 下会失败**。pmbootstrap 默认用 crossdirect 交叉编译（在 aarch64 chroot 里通过 `/native` 绑定挂载调用宿主机的交叉 gcc）。WSL2 里这个绑定挂载没有生效，编译 `device-xiaomi-marble` 时报：

   ```
   cc: fatal error: cannot execute 'cc1': posix_spawnp: No such file or directory
   ```

   只需加全局开关 `--no-cross` 改成纯 QEMU 编译即可（设备包只有一个几百行的 C 文件，QEMU 慢一点无所谓）：

   ```bash
   pmbootstrap --no-cross -y build device-xiaomi-marble
   ```

   注意：内核包（`linux-xiaomi-marble`）自己带 `pmb:cross-native` 选项，不受影响，正常编就行。

9. **`install` 在无 TTY 环境会卡在密码输入**。脚本里调用 `pmbootstrap install` 时会交互式要求为普通用户设密码，非交互环境（CI、后台任务、管道）会抛 `termios.error: Inappropriate ioctl for device` / `EOFError`。必须用 `--password` 显式传：

   ```bash
   pmbootstrap -y install --split --password '<你的密码>'
   ```

   > ⚠️ `--password` 是明文传递的，会写进 pmbootstrap 日志。建议生成随机密码、装完立刻 `passwd` 改掉，并且不要在日志里留存太久。

```bash
# 需要 LUKS 加密的话：
# pmbootstrap -y install --split --fde --add postmarketos-buffybox-unl0kr
```

### 分区对照表

| 分区 | 设备 | 大小 | 内容 |
|---|---|---|---|
| `boot_a` | `/dev/block/sde14` | 192MB | Android 内核（不动） |
| `boot_b` | `/dev/block/sde42` | 192MB | **U-Boot** |
| `persist` | `/dev/block/sdf7` | 32MB | **IMEI/校准，必须备份** |
| `modemst1` | `/dev/block/sdf3` | 8MB | **射频校准，必须备份** |
| `modemst2` | `/dev/block/sdf4` | 8MB | **射频校准，必须备份** |
| `fsg` | `/dev/block/sdf5` | 8MB | **射频校准，必须备份** |
| `userdata` | `/dev/block/sda33` | 224GB | Android 数据（single 布局会被删） |
| `esp` | `/dev/sda34` | 1G | ext2 `pmOS_boot`：内核/initramfs/DTB/extlinux.conf |
| `pmos` | `/dev/sda35` | 剩余 | ext4 `pmOS_root`：根文件系统 |

> 存储是 **4096 字节扇区**，别用假设 512 字节的工具手工分区。
